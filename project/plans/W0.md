## Gate hook (`.claude/hooks/gate.py`)
It reads JSON from stdin. **Any exception, missing field, or missing or unknown `project/STAGE` blocks with exit 2.** Actor = `agent_type` if present, otherwise `lead`. Any other agent type (built-ins such as general-purpose) is treated as read-only.

1. **Read/Grep/Glob:** block `developer` on `datasets/holdout/**`, and block everyone on `.env.lab`. Everything else is allowed.
2. **Edit/Write/NotebookEdit:** resolve the realpath against `CLAUDE_PROJECT_DIR` (symlinks and `..` can't escape).
   - Always blocked: `project/approvals/**`, `.env.lab`, and `.claude/hooks/**`, `.claude/settings.json`, `scripts/approve.sh` once W0 is closed.
   - Outside the repo: only the plan-mode dir, the memory dir and the session scratchpad are allowed.
   - **Process paths** (`project/plans/`, `project/notes/`, `project/reports/`, `project/STAGE`, `project/STATUS.md`) need no approval, but agent scope still applies: planner → `plans/`; developer and lab-ops → `notes/`; evaluator → `reports/<stage>/eval/`; reviewers → their own `reports/<stage>/{telco,security}.md`; lead → `STAGE`, `STATUS.md`, `notes/`, `reports/<stage>/close.md`.
   - **Everything else** must be inside the actor's product scope (section 5 table) **and** pass this check: `sha256(project/plans/<STAGE>.md) == project/approvals/<STAGE>.plan.sha256`. Editing the plan breaks the match and the approval is void. The lead's product scope is empty, except during `W0`, when it is `.claude/ project/ scripts/ CLAUDE.md .gitignore docs/roadmap/ docs/agent-gate.md DEVLOG.md`.
3. **Bash** (checks run on the command text after normalizing whitespace and quotes):
   - Mentions of `project/approvals`, `approve.sh` or `.env.lab` are blocked for everyone.
   - **Lab-changing commands** run only for `lab-ops` with an approved plan: `terraform apply|import|destroy|state rm|taint`; `ansible-playbook`; `qm`/`pct` (any subcommand except `list|status|config|listsnapshot`); `pvesh create|set|delete`; `curl -X POST/PUT/DELETE` to `:8006`; `helm install|upgrade|uninstall|rollback`; `kubectl apply|create|delete|replace -f` (the manifests contain Namespace objects); `kubectl` mutations of cluster-scoped kinds (node, namespace, crd, clusterrole*, storageclass, pv, helmchart) or anything in `kube-system`/`-A`; `ssh`/`scp` to lab hosts.
   - **Namespaced, project-CLI operations** in `neoncore`/`monitoring` (`kubectl exec|logs|get|delete pod|scale deploy`, `python3 -m phase6.cli`) are allowed for any agent once the stage plan is approved. Read-only `kubectl get/describe/logs` is always allowed.
   - **Destructive commands are blocked for everyone**, so you run them yourself: `git push --force`, `git branch -D`, `git reset --hard`, `git rebase`, `git clean -f`, `kubectl delete namespace`, `rm -rf` outside the scratchpad.
   - **File writes through Bash** (`>`, `>>`, `tee`, `sed -i`, `cp`, `mv`, `rm`, `touch`, `mkdir`, `git checkout --`, `git restore`): extract the target paths and apply rule 2. If the target can't be determined, the command is blocked unless the actor has a write scope that covers the cwd.
   - Reads of `datasets/holdout` by `developer` are blocked.
4. Every block prints `GATE BLOCKED [actor] reason` to stderr and exits 2.

`docs/agent-gate.md` states plainly that this parses Bash text. It catches mistakes, not a determined adversary: aliases, encoded commands, and Python subprocesses (the TUI's own `kubectl` calls) are invisible to it.

## `scripts/approve.sh <stage> <plan|close>`
It refuses unless `[ -t 0 ] && [ -t 1 ]` **and** `CLAUDECODE` is unset (Claude Code sets that variable in its own shells). It prints the plan's or `reports/<stage>/close.md`'s `#` title, path, SHA-256 and `git log -1` for that file, then requires typing `APPROVE` exactly. It writes `project/approvals/<stage>.<kind>.sha256` (hash, path, UTC time, `$USER`), sets it to `chmod 444`, and prints a reminder to commit it yourself.

## `.claude/settings.json`
```json
{ "permissions": {
    "deny": ["Read(/.env.lab)", "Edit(/project/approvals/**)", "Write(/project/approvals/**)",

             "Edit(/.claude/hooks/**)", "Edit(/.claude/settings.json)", "Edit(/scripts/approve.sh)"],

  "enabledPlugins": { "…": "written by claude plugin install --scope project" } }
```
The three self-protecting deny rules are written in the **final** W0 step, as you specified.

## Skills
- **/plan-stage `<id>`**: checks that the previous stage's close approval exists and its hash matches. Sets `STAGE` and `STATUS`. Runs phase-planner → evaluator (metrics and thresholds) → telco-reviewer and security-reviewer comments. Summarizes for you, then **stops**.
- **/build-stage `<id>`**: checks the plan approval hash. Creates branch `stage/<id>`. Hands out tasks by owner. Requires lab deploy and verification. Counts failed cycles and stops after 3 failures on the same issue.
- **/close-stage `<id>`**: runs evaluator and reviewers independently, then docs-writer and blog-writer. The lead writes `reports/<id>/close.md` (evidence, numbers with source files, spend, limits, 5–10 questions). Asks you to run `approve.sh <id> close`, then merges locally. Pushing is a separate approval.
- **/lab-status**: read-only. Shows pods in both namespaces, tracer liveness (newest pcap growing), the SMF↔UPF association in the logs, Proxmox VM state, and snapshots through API GETs. Before L0 it reports "no lab".
